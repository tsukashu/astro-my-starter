# 品質チェック表

## 必須項目（7項目）

### SEO・メタ情報

- [ ] タイトル・ディスクリプション（必須）: TDK Meta Checker
- [ ] OGP が設定されているか（必須）: TDK Meta Checker
- [ ] 見出し構造が自然か（必須）: HeadingsMap

### 表示・ブランド

- [ ] ファビコン（必須）: 目視確認
- [ ] クロスブラウザ表示（必須）: Chrome / Firefox / Safari / Edge で目視確認

### 技術品質

- [ ] HTML / CSS 構文チェック（必須）: HTML → Nu Html Checker / CSS → W3C CSS Validator
- [ ] 閉じタグチェック（必須）: Nu Html Checker

## その他項目

### レイアウト・レスポンシブ

- [ ] スムーズにレスポンシブ化されるか: レスポンシブデザインモードで目視確認
- [ ] 5パターン（320 / 375 / 768 / PCカンプ / 1920px）の崩れ: レスポンシブデザインモードで目視確認
- [ ] 水平スクロールしないか: レスポンシブデザインモードで確認

### コンテンツ・アクセシビリティ

- [ ] 誤字脱字がないか: テキスト比較ツールで比較
- [ ] 改行位置は適切か: タブレット・スマホ時の `<br>` の改行位置を確認
- [ ] フォントは適切か: DevTools の「レンダリングフォント」を確認
- [ ] alt が正しいか: 画像ALTチェッカー、Alt & Meta viewer

### 挙動・リンク

- [ ] リンク・ボタンのホバー挙動: 実際に操作して確認
- [ ] JavaScript の挙動: 実際に操作して確認
- [ ] リンク切れ: 各リンクを実際にクリックして確認（公開サイトなら Frog でも確認可能）
- [ ] コンソールエラー: DevTools のコンソール確認

### 画像・パフォーマンス

- [ ] 画像圧縮: tinypng などの圧縮サービスで確認
- [ ] 画像が同じか: 目視確認
- [ ] デザインカンプとの差異: カンプを書き出し → PerfectPixel で比較

## 補足: コーディング後のチェックの重要性について

- クライアントは、仕様どおり・デザインどおりにコーディングされていることを前提条件としている。
- 継続して依頼されるのは、品質を安定して担保できるコーダー
- 品質チェックは経験年数やスキルではなく、「どれだけ意識して運用しているか」の問題
- 構文チェックやクロスブラウザ確認などの基本項目を、毎回チェックリストとして実行することで信頼を積み上げられる
